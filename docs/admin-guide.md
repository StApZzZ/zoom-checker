## 1. Как устроен сервис

```
Zoom ──webhook (HTTPS, подпись HMAC)──▶ Zoom Checker ──▶ база (SQLite или PostgreSQL)
                                           │
                                           └── живые обновления (SSE) ──▶ браузер преподавателя
```

* Zoom присылает события «конференция началась / закончилась», «участник вошёл / вышел»
  (и вход/выход из комнат для групповой работы).
* Каждое событие **сначала сохраняется как есть**, потом обрабатывается. Повторная доставка
  ничего не дублирует; если обработка временно не удалась, событие обрабатывается повторно.
* Посещаемость каждого занятия пересчитывается из сохранённых событий, поэтому ручные
  исправления, поздно пришедшие события и изменения списка группы всегда дают согласованный результат.
* Участник Zoom сопоставляется со студентом **только по точному совпадению имени** после
  нормализации (регистр, лишние пробелы, «ё»→«е», невидимые символы). Никакого «угадывания»:
  неопознанные имена показываются преподавателю отдельно, он может сопоставить их вручную.
* Это один исполняемый файл (~27 МБ) со встроенным веб-интерфейсом. В простое занимает ~25 МБ
  памяти. По умолчанию данные хранятся во встроенной SQLite — отдельная СУБД не нужна.

## 2. Требования

* Linux x86-64 или ARM64 с systemd (Oracle Linux / RHEL / Alma / Rocky 8–10, Debian, Ubuntu…)
  **или** любой хост с Docker.
* 1 vCPU, 256 МБ RAM, 1 ГБ диска — с запасом для нескольких сотен занятий в месяц.
* Публичный адрес, доступный из интернета по HTTPS: Zoom отправляет события только на https.
  Для встроенного получения сертификата должны быть открыты порты **80 и 443**
  ([как открыть их у облачного провайдера](#откройте-порты-80-и-443-у-облачного-провайдера)).
* **Доменное имя** (A-запись в DNS на IP-адрес сервера). Для Zoom оно нужно обязательно: так требует
  Zoom — адрес для событий должен быть доменным именем, IP-адрес Zoom не примет. Без имени сервис
  всё равно получит сертификат Let's Encrypt прямо на IP-адрес и веб-интерфейс откроется — так можно
  начать, а имя добавить позже ([как перейти с IP на доменное имя](#перейти-с-ip-адреса-на-доменное-имя)).

### Откройте порты 80 и 443 у облачного провайдера

Если сервер арендован в облаке (Yandex Cloud, VK Cloud, Selectel, AWS и т. п.), входящие соединения
обычно закрывает не сам сервер, а «группа безопасности» (security group) или «firewall» в панели
провайдера. Установщик открывает порты только во встроенном брандмауэре сервера (firewalld или ufw)
и проверяет работу изнутри сервера — поэтому он сообщит, что всё запущено, даже если снаружи сервер
недоступен. Пока порты закрыты, Let's Encrypt не выдаст сертификат (он проверяет сервер через порты
80 и 443), а Zoom не пройдёт проверку **Validate** (события приходят на порт 443).

Что сделать: в группе безопасности (firewall), привязанной к этой виртуальной машине, добавьте два
правила для **входящего** трафика: протокол TCP, порт **80** и порт **443**, источник — любой адрес
(`0.0.0.0/0`, а если используется IPv6 — ещё и `::/0`). Где это обычно находится (названия
в панелях иногда меняются):

| Провайдер | Где искать |
|---|---|
| Yandex Cloud | «Virtual Private Cloud» → «Группы безопасности» → группа, назначенная вашей ВМ |
| VK Cloud | «Виртуальные сети» → «Настройки firewall» |
| Selectel | облачный файрвол или группы безопасности — если они включены для сервера |
| AWS | «EC2» → «Security Groups» → группа сервера → «Inbound rules» |
| Другой хостинг | панель управления сервером; если не нашли — спросите поддержку хостинга |

Проверка (при `TLS_MODE=auto`, как настраивает установщик) — **с другого компьютера** (например,
с домашнего ноутбука или с телефона через мобильный интернет), а не с самого сервера:

1. Откройте в браузере `http://<адрес сервера>/healthz` — должно появиться слово `ok`.
2. Откройте `https://<адрес сервера>` — должна открыться страница входа без предупреждения о сертификате.

Если страница долго грузится и браузер пишет, что время ожидания истекло, — порты всё ещё закрыты.
Если `/healthz` открывается, а `https://` — нет или с предупреждением, подождите минуту: сертификат
ещё получается. Причину ошибки показывает журнал (`journalctl -u zoom-checker`, строка
`could not obtain TLS certificate`).

## 3. Установка на сервер одной командой

Нужен пакет установки: бинарник `zoom-checker-linux-amd64` (или `-arm64` для ARM-сервера),
`install.sh`, `zoom-checker.service` и `.env.example` — шаблон настроек с пояснениями.

### Как получить пакет установки

**Скачать готовый.** Пакет каждой версии лежит на странице [Releases](https://github.com/StApZzZ/zoom-checker/releases) одним
архивом `zoom-checker-linux.tar.gz`. Последнюю версию можно скачать прямо на сервере:

```bash
curl -fLO https://github.com/StApZzZ/zoom-checker/releases/latest/download/zoom-checker-linux.tar.gz
```

**Собрать самому** из исходного кода. Подойдёт любой компьютер с Linux или macOS (в Windows — в WSL),
где есть Go 1.26 или новее, Node.js 22, `make` и интернет; сам сервер для этого не нужен.

```bash
git clone https://github.com/StApZzZ/zoom-checker.git && cd zoom-checker
make package                                       # соберёт пакет: dist/zoom-checker-linux.tar.gz
scp dist/zoom-checker-linux.tar.gz admin@server:   # admin@server — ваш вход на сервер по SSH
```

Копируйте пакет одним архивом: если копировать файлы по одному, легко потерять скрытый файл
`.env.example`.

### Установка

На сервере распакуйте пакет и запустите установщик из его папки:

```bash
mkdir zoom-checker && tar -xzf zoom-checker-linux.tar.gz -C zoom-checker && cd zoom-checker
sudo ./install.sh --public-url https://attendance.example.com
```

Установщик спросит Secret Token из Zoom ([раздел 6](#6-подключение-zoom)): вставьте его — на экране
он не показывается. Если токена ещё нет, нажмите Enter и добавьте его позже, запустив установщик ещё
раз. Можно запустить и совсем без параметров — установщик сам спросит и адрес.
Что делает `install.sh` (повторный запуск безопасен):

1. копирует бинарник в `/usr/local/bin/zoom-checker`;
2. создаёт системного пользователя `zoom-checker`, каталоги `/etc/zoom-checker` и `/var/lib/zoom-checker`;
3. создаёт файл настроек `/etc/zoom-checker/zoom-checker.env` (если его ещё нет), права `0640`;
4. **проверяет настройки** (`zoom-checker check-config`) от имени пользователя службы — при ошибке
   останавливается, ничего не ломая;
5. устанавливает защищённый systemd-юнит, открывает порты в firewalld/ufw (если они включены),
   запускает сервис и ждёт ответа `/healthz` (изнутри сервера — доступность из интернета проверьте
   сами, см. [раздел 2](#откройте-порты-80-и-443-у-облачного-провайдера));
6. печатает адрес сервиса, адрес для Zoom и данные первого входа.

Полезные ключи: `--zoom-secret-file ФАЙЛ` (взять Secret Token из файла — для установки без вопросов),
`--tls auto|off|file`, `--port N` (порт для `--tls off` и `--tls file`), `--timezone ПОЯС` (например
`Asia/Yekaterinburg`; без него установщик берёт часовой пояс сервера, а если на сервере стоит UTC —
`Europe/Moscow`, и при установке с вопросами спрашивает), `--binary ПУТЬ`, `--url URL` (скачать бинарник
по прямой ссылке на файл `zoom-checker-linux-amd64` или `-arm64`, например со страницы Releases или своего файлового сервера;
принимаются только адреса `https://`; вместе с ним укажите `--sha256 СУММА` из файла `SHA256SUMS`),
`-y` (без вопросов), `--uninstall [--purge]`. Пакет из `make release` можно проверить и вручную:
`sha256sum -c SHA256SUMS` в его папке; локальный бинарник установщик сверяет с `SHA256SUMS` сам.
Для `--tls file` в файле настроек должны быть указаны `TLS_CERT_FILE` и `TLS_KEY_FILE`
([раздел 5](#свой-сертификат-tls_modefile)). При первой установке установщик создаст файл настроек и
остановится на проверке — впишите в него пути к сертификату и запустите установщик ещё раз.

После установки:

```bash
systemctl status zoom-checker
journalctl -u zoom-checker -f
sudo nano /etc/zoom-checker/zoom-checker.env      # изменить настройки
sudo -u zoom-checker /usr/local/bin/zoom-checker check-config && sudo systemctl restart zoom-checker
```

Последняя команда сначала проверяет настройки **от имени пользователя службы** `zoom-checker` — так,
как их увидит сам сервис (например, сможет ли он прочитать файл ключа или сертификата), — и только
если всё в порядке, перезапускает сервис. Полный путь `/usr/local/bin/zoom-checker` нужен: в Oracle
Linux, RHEL, Alma и Rocky Linux `sudo` не ищет программы в `/usr/local/bin`. То же самое делает
повторный запуск `sudo ./install.sh` из папки с пакетом.

## 4. Установка в Docker

См. [deploy/README-docker.md](../deploy/README-docker.md). Кратко — в папке с исходным кодом
Zoom Checker (распакованный архив или `git clone`; образ собирается из него):

```bash
cd deploy
cp .env.example .env && chmod 600 .env   # в файле будут пароли — читать его может только владелец
nano .env                                # укажите PUBLIC_URL и ZOOM_WEBHOOK_SECRET_TOKEN
docker compose up -d --build
```

Образ ~30 МБ (distroless, не root). Данные — в томе `/data`. PostgreSQL включается строкой
`COMPOSE_PROFILES=postgres` в `.env`. Пароль базы (`POSTGRES_PASSWORD`) составьте только из
латинских букв и цифр, например `openssl rand -hex 24`: символы вроде `@ / %` и пробел ломают строку
`DATABASE_URL`, и сервис не сможет подключиться к базе.

Команды из этого руководства в Docker выполняются так: `docker compose exec zoom-checker /zoom-checker <команда>`
в работающем контейнере или `docker compose run --rm zoom-checker <команда>` — этот вариант работает,
даже если контейнер не запускается.

**Файлы сертификатов в Docker.** Контейнер не видит папки сервера, поэтому пути вида
`/etc/zoom-checker/…` из разделов 5, 8 и 9 в Docker не работают: с ними сервис не запустится и будет
перезапускаться по кругу (вход перестанет работать у всех). Если нужны `LDAP_CA_FILE`, `OIDC_CA_FILE`
или свой сертификат (`TLS_MODE=file`):

1. В папке `deploy` создайте папку `certs`, положите в неё файлы и отдайте их пользователю
   контейнера (UID 65532): `sudo chown -R 65532:65532 certs`. Файл ключа, если он есть, закройте
   от остальных: `sudo chmod 600 certs/tls.key`.
2. В `docker-compose.yml` в разделе `volumes:` сервиса `zoom-checker` добавьте строку `- ./certs:/certs:ro`
   (если она там уже есть с `#` в начале — просто уберите `#`).
3. В `.env` укажите пути **внутри контейнера**: `LDAP_CA_FILE=/certs/corp-ca.pem`,
   `OIDC_CA_FILE=/certs/keycloak-ca.pem`, `TLS_CERT_FILE=/certs/tls.crt`, `TLS_KEY_FILE=/certs/tls.key`.
4. Проверьте настройки и запустите:

   ```bash
   docker compose run --rm zoom-checker check-config
   docker compose run --rm zoom-checker check-ldap --user ivanov   # если настроен LDAP
   docker compose up -d
   ```

Если `docker compose ps` показывает «Restarting», причину покажет `docker compose logs zoom-checker`
(ищите строки `LDAP settings`, `OIDC settings` или `TLS_CERT_FILE`).

## 5. HTTPS

| Режим `TLS_MODE` | Когда использовать |
|---|---|
| `auto` | Сервис сам получает и продлевает сертификат Let's Encrypt. Нужны открытые порты 80 и 443 ([раздел 2](#откройте-порты-80-и-443-у-облачного-провайдера)). Работает для доменного имени и для голого IP-адреса (Let's Encrypt выдаёт IP-сертификаты на 6 дней, сервис продлевает их сам), но **Zoom принимает только адрес с доменным именем**. |
| `off` | Перед сервисом стоит ваш nginx / Caddy / балансировщик, который делает HTTPS. Сервис слушает `LISTEN_ADDR` (по умолчанию `:8080`). Укажите `TRUSTED_PROXIES`. |
| `file` | Свой сертификат: `TLS_CERT_FILE`, `TLS_KEY_FILE`. Сервис сам отдаёт HTTPS на `LISTEN_ADDR` — обычно нужно указать `LISTEN_ADDR=:443` ([ниже](#свой-сертификат-tls_modefile)). |

Для nginx перед сервисом отключите буферизацию живых обновлений:

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;          # SSE: обновления без задержек
    proxy_read_timeout 1h;
}
```

### Свой сертификат (`TLS_MODE=file`)

```
TLS_MODE=file
TLS_CERT_FILE=/etc/zoom-checker/tls.crt   # сертификат вместе с цепочкой (fullchain)
TLS_KEY_FILE=/etc/zoom-checker/tls.key
LISTEN_ADDR=:443
```

* Сервис отдаёт HTTPS на `LISTEN_ADDR`, а по умолчанию это `:8080`. Для обычного адреса
  `https://attendance.example.com` укажите `LISTEN_ADDR=:443` и откройте порт 443. Права root для этого не нужны:
  служба уже может занимать порты ниже 1024. Установщик делает то же самое ключами `--tls file --port 443`.
* Сервис работает от пользователя `zoom-checker`, поэтому файлы должны читаться им. Не кладите их в
  `/home` и `/root` — служба эти папки не видит. Удобнее всего держать их в `/etc/zoom-checker`:

  ```bash
  sudo chown root:zoom-checker /etc/zoom-checker/tls.crt /etc/zoom-checker/tls.key
  sudo chmod 0640 /etc/zoom-checker/tls.crt /etc/zoom-checker/tls.key
  ```

* Обновлённые файлы сервис подхватывает сам в течение ~30 секунд, перезапуск не нужен.
* Сертификат от certbot: файлы в `/etc/letsencrypt` читает только root, поэтому пусть certbot сам
  копирует их при каждом продлении — добавьте к своей команде `certbot` параметр
  `--deploy-hook 'install -m 0640 -o root -g zoom-checker "$RENEWED_LINEAGE/fullchain.pem" /etc/zoom-checker/tls.crt && install -m 0640 -o root -g zoom-checker "$RENEWED_LINEAGE/privkey.pem" /etc/zoom-checker/tls.key'`.
  Проще — `TLS_MODE=auto`: сервис сам получит и продлит сертификат Let's Encrypt.
* Проверка: `sudo -u zoom-checker /usr/local/bin/zoom-checker check-config`.

### Перейти с IP-адреса на доменное имя

Zoom требует, чтобы адрес для событий (*Event notification endpoint URL*) был доменным именем: на
адрес вида `https://203.0.113.10/api/webhooks/zoom` Zoom события не отправляет, и проверка
**Validate** не проходит. Веб-интерфейс по IP при этом работает. Чтобы перейти на имя:

1. В DNS вашей организации (или у регистратора домена) заведите A-запись: имя, например
   `attendance.example.com`, → IP-адрес сервера. Проверка с любого компьютера: `nslookup attendance.example.com`
   показывает IP сервера.
2. Укажите новое имя в `PUBLIC_URL`:
   * установка через `install.sh` — из папки с пакетом: `sudo ./install.sh --public-url https://attendance.example.com`
     (остальные настройки сохранятся, сервис перезапустится);
   * Docker — в `.env` замените `PUBLIC_URL` и выполните `docker compose up -d`.

   Сертификат на имя сервис получит сам за минуту. Если сервис нужен и по старому IP-адресу,
   добавьте его в `TLS_EXTRA_HOSTS`.
3. Zoom Marketplace → ваше приложение → **Feature** → **Event Subscriptions**: замените
   *Event notification endpoint URL* на `https://attendance.example.com/api/webhooks/zoom` →
   **Validate** → **Save**.
4. Если настроен вход через Keycloak — в клиенте `zoom-checker` замените адреса в
   *Valid redirect URIs* (`https://attendance.example.com/auth/oidc/callback`) и
   *Valid post logout redirect URIs* (`https://attendance.example.com/login`).

## 6. Подключение Zoom

События приходят только по конференциям, **организатором которых является пользователь
вашего аккаунта Zoom**. Нужна роль владельца или администратора аккаунта Zoom (или роль с правом
«Zoom for developers: View + Edit»).

1. Откройте <https://marketplace.zoom.us> → **Develop → Build App**.
2. Выберите **Server-to-Server OAuth App** (рекомендуется; подойдёт и **Webhook Only App**) → *Create*, введите имя, например «Zoom Checker».
3. **Information**: заполните краткое описание, название компании, имя и e-mail разработчика.
4. **Feature**:
   * скопируйте **Secret Token** → в настройку `ZOOM_WEBHOOK_SECRET_TOKEN`, перезапустите сервис;
   * включите **Event Subscriptions** → **Add Event Subscription**, имя — любое;
   * **Event notification endpoint URL**: `https://<ваш адрес>/api/webhooks/zoom` — адрес с доменным
     именем, IP-адрес Zoom не примет ([раздел 5](#перейти-с-ip-адреса-на-доменное-имя)). Точный адрес
     показан на странице «Zoom» в приложении — кнопка «Скопировать»;
   * чьи события: **All users in your account**;
   * **Add Events → Meeting**: отметьте
     * *Start Meeting*,
     * *End Meeting*,
     * *Participant/Host joined meeting*,
     * *Participant/Host left meeting*,
     * *Meeting participant has joined a breakout room*,
     * *Meeting participant has left a breakout room*;
   * нажмите **Validate** (сервис должен быть запущен с уже указанным секретом) → должно появиться «Validated» → **Save**.
5. **Scopes**: проверьте, что есть `meeting:read:participant:admin` и `meeting:read:meeting:admin` (при необходимости *Add Scopes*).
6. **Activation** → **Activate your app**.

Проверка: на странице **Zoom** в приложении после любой конференции появится зелёный статус
«Zoom присылает события», а в «Журнале событий» (меню администратора) — сами события.
Без настоящего Zoom работу можно показать командой `zoom-checker simulate` ([раздел 13](#13-командная-строка)).

### Если сервис был недоступен

Zoom проверяет адрес каждые 72 часа. Если сервис не ответил на событие, Zoom повторяет его ещё 3 раза —
примерно через 5, 25 и 85 минут, — а после этого событие пропадает навсегда. Поэтому:

* перерыв до ~1,5 часа (перезапуск, обновление) не страшен — события дойдут сами;
* после более долгого перерыва события за это время уже не придут. Откройте занятия, которые шли во
  время перерыва. Если занятие так и осталось в статусе «Идёт», на его странице через час после конца
  по расписанию появится жёлтый блок «Zoom не сообщил, что конференция закончилась» — нажмите в нём
  (или в **Действия**) **Завершить занятие** и укажите настоящее время окончания. Если из Zoom 6 часов
  ничего не приходит, сервис завершает такое занятие сам — по последнему событию из Zoom (в истории
  занятия автор — «Система»). Проверьте отметки «Был / Не был» и при необходимости исправьте их вручную:
  у студентов, которые так и остались «В Zoom», время считается до завершения занятия и может быть завышено;
* если сервис был недоступен больше двух недель, Zoom может сам отключить подписку (перед этим
  владельцу аккаунта Zoom приходят письма). Как включить её снова — в [разделе 14](#14-если-что-то-не-работает).

### Одна конференция Zoom — одно занятие

Каждый запуск конференции Zoom (от начала до завершения) засчитывается **только одному занятию** с тем
же номером конференции. Сервис выбирает так:

* конференция началась во время занятия (по расписанию) — это занятие;
* конференцию перезапустили, когда занятие затянулось (не позже чем через 10 минут после того, как
  предыдущий запуск закончился), — то же занятие;
* конференцию открыли заранее — занятие, которое скоро начнётся: не раньше чем за **1 час** до начала
  (настройка «Окно привязки» в **Админ → Настройки**);
* иначе — занятие, которое закончилось не больше 30 минут назад.

Конференция, которая началась позже или раньше этих границ (например, коллега в другой день провёл
встречу по тому же личному номеру Zoom), ни к какому занятию сама не привяжется — она будет на
странице **Zoom** среди несвязанных. Обычно это именно то, что нужно. Но в двух случаях второе занятие
останется «Запланировано», а все его студенты — «Не подключался»:

* **Совместная лекция для нескольких групп по одной ссылке.** Посещаемость посчитается только
  у одной группы, а студенты остальных групп окажутся у неё в «Не идентифицированы». Что делать:
  * создайте общую группу (поток) со студентами всех групп и одно занятие для неё;
  * или, если важна посещаемость одной конкретной группы, привяжите конференцию к её занятию вручную:
    страница **Zoom** → переключатель «Все» → строка конференции → **Другое занятие**. Остальным группам
    отметки «Был / Не был» придётся поставить вручную.
* **Два занятия подряд по одной ссылке, а конференция всё это время идёт** (сдвоенная пара или
  занятия разных групп друг за другом). Всё время засчитается первому занятию. Что делать:
  * для разных групп используйте разные конференции Zoom;
  * или преподаватель между занятиями завершает конференцию в Zoom («Завершить конференцию для всех»)
    и запускает её снова к началу второго занятия по расписанию — новый запуск сам привяжется ко
    второму занятию (запуск сразу после окончания затянувшегося первого занятия сервис считает его
    продолжением);
  * сдвоенную пару одной группы проще создать одним занятием на всё время.

Если занятия уже прошли, конференцию можно перепривязать к нужному занятию так же: страница
**Zoom** → «Все» → **Другое занятие**. Если к занятию привязалась чужая конференция, преподаватель
может отвязать её прямо на странице занятия: блок **«Конференции Zoom»** → **«Это другая конференция»**.

## 7. Первый вход и пользователи

* Логин первого администратора — `admin` (настройка `ADMIN_USERNAME`).
* Пароль: задайте `ADMIN_PASSWORD` до первого запуска **или** возьмите сгенерированный из файла
  `/var/lib/zoom-checker/initial-admin-password.txt` (установщик печатает его сам).
  * Сгенерированный пароль сервис попросит сменить при первом входе, после чего файл удаляется.
  * Пароль из `ADMIN_PASSWORD` сервис попросит сменить, только если он слишком простой (например, короче
    8 символов). Надёжный пароль остаётся как есть — поэтому после первого входа смените его сами
    (меню с вашим именем → «Сменить пароль») и удалите строку `ADMIN_PASSWORD` из файла настроек:
    она нужна только при первом запуске, пока в базе нет ни одного пользователя.
* Роли: **администратор** (всё, включая пользователей, настройки и журнал событий Zoom) и
  **преподаватель** (группы, занятия, посещаемость, выгрузки).
* Локальные учётные записи создаются в **Админ → Пользователи**. Пользователи Keycloak и AD
  появляются там автоматически после первого входа; их роль определяется группами/ролями
  в Keycloak/AD при каждом входе.
* Вход действует ограниченное время **с момента входа** (работа в сервисе его не продлевает), потом
  нужно войти снова: для локальных учётных записей — `SESSION_TTL` (по умолчанию 7 дней), для Keycloak и
  AD — `EXTERNAL_SESSION_TTL` (по умолчанию 24 часа). При новом входе роль и блокировка заново берутся
  из Keycloak/AD: если сотрудника убрали из группы или отключили там, доступ пропадёт не позже чем через
  `EXTERNAL_SESSION_TTL`.
* Чтобы закрыть доступ **сразу**, отключите пользователя в **Админ → Пользователи**: он потеряет доступ
  при следующем действии, а открытые страницы занятий перестанут обновляться в течение минуты.
* Забыли пароль администратора: `sudo /usr/local/bin/zoom-checker user set-password admin --generate` —
  новый пароль будет показан один раз (в Docker: `docker compose exec zoom-checker /zoom-checker user set-password admin --generate`).

## 8. Вход через Keycloak (OpenID Connect)

В Keycloak (realm вашей организации):

1. **Clients → Create client**: Client type *OpenID Connect*, Client ID `zoom-checker`.
2. *Client authentication*: **On** (конфиденциальный клиент), *Standard flow*: **On**, остальные потоки — Off.
3. *Valid redirect URIs*: `https://<ваш адрес>/auth/oidc/callback`;
   *Valid post logout redirect URIs*: `https://<ваш адрес>/login`; *Web origins*: `+`.
4. Вкладка **Advanced**: *Proof Key for Code Exchange Code Challenge Method* = `S256`.
5. Вкладка **Credentials**: скопируйте *Client secret*.
6. **Realm roles → Create role**: `zoom-checker-teacher` и `zoom-checker-admin`. Назначьте их
   пользователям или группам (у пользователя или группы: *Role mapping → Assign role*). Это
   рекомендуемый способ — дополнительная настройка не нужна. Роли клиента `zoom-checker` тоже подходят.
7. *Необязательно.* Если хотите указывать в настройках сами группы Keycloak (без ролей), Keycloak нужно
   попросить передавать их: **Clients → zoom-checker → вкладка Client scopes → zoom-checker-dedicated →
   Configure a new mapper** (или *Add mapper → By configuration*) → **Group Membership**.
   *Name*: `groups`, *Token Claim Name*: `groups`, *Full group path*: **On**, *Add to ID token*,
   *Add to access token* и *Add to userinfo*: **On** → *Save*. Без этого шага группы до сервиса не
   доходят, и вход будет запрещён всем. После него в `OIDC_TEACHER_ROLES` можно писать полный путь
   группы (`/staff/teachers`) или просто её имя (`teachers`). Учитывается только прямое членство:
   участники подгруппы `/staff/teachers/math` в группу `/staff/teachers` не входят.

Настройки сервиса:

```
OIDC_ISSUER_URL=https://sso.example.com/realms/edu
OIDC_CLIENT_ID=zoom-checker
OIDC_CLIENT_SECRET=<Client secret>
OIDC_TEACHER_ROLES=zoom-checker-teacher
OIDC_ADMIN_ROLES=zoom-checker-admin
OIDC_BUTTON_LABEL=Войти через корпоративный аккаунт
```

Важно: **по умолчанию доступ не получает никто**, пока не указаны `OIDC_TEACHER_ROLES` /
`OIDC_ADMIN_ROLES` — в realm учебной организации обычно есть и студенты. Значение `*` в
`OIDC_TEACHER_ROLES` пускает всех пользователей realm. Пользователь без нужной роли увидит
понятное сообщение с названием роли и кнопку «Войти под другой учётной записью».

* Несколько ролей или групп перечисляются через запятую.
* Если вы включили передачу групп (шаг 7), простое имя в `OIDC_ADMIN_ROLES` совпадёт и с группой
  с таким же названием на любом уровне — например, `zoom-checker-admin` совпадёт с
  `/students/zoom-checker-admin`. Поэтому, если администраторов назначает группа, указывайте её
  полный путь: `OIDC_ADMIN_ROLES=/staff/zoom-checker-admin`. У ролей realm пути нет — с ними всё как есть.
* Если сертификат Keycloak выпущен внутренним центром сертификации организации, укажите
  `OIDC_CA_FILE=/etc/zoom-checker/keycloak-ca.pem`. Файл должен читаться службой:
  `sudo chown root:zoom-checker /etc/zoom-checker/keycloak-ca.pem && sudo chmod 0640 /etc/zoom-checker/keycloak-ca.pem`.
  В Docker путь указывается внутри контейнера — см. [раздел 4](#4-установка-в-docker).

Проверка: `sudo -u zoom-checker /usr/local/bin/zoom-checker check-oidc`
(в Docker: `docker compose run --rm zoom-checker check-oidc`).

## 9. Вход через Active Directory / LDAP

Пользователь вводит свой обычный логин (`ivanov`, `CORP\ivanov` или `ivanov@corp.example.com`)
и пароль на странице входа сервиса. Пример для Active Directory:

```
LDAP_URL=ldaps://dc1.corp.example.com:636
LDAP_PRESET=ad
LDAP_BASE_DN=DC=corp,DC=example,DC=com
LDAP_BIND_DN=CN=svc-zoom-checker,OU=Service,DC=corp,DC=example,DC=com
LDAP_BIND_PASSWORD=<пароль служебной учётной записи>
LDAP_TEACHER_GROUPS=ZoomChecker-Teachers
LDAP_ADMIN_GROUPS=CN=ZoomChecker-Admins,OU=Groups,DC=corp,DC=example,DC=com
LDAP_CA_FILE=/etc/zoom-checker/corp-ca.pem
```

* Служебной учётной записи достаточно прав обычного пользователя домена (чтение каталога).
  Без неё (`LDAP_BIND_DN` пустой) для AD можно указать `LDAP_DOMAIN=corp.example.com` —
  тогда сервис входит прямо от имени пользователя.
* Группы указываются полным DN или просто именем (CN), **через точку с запятой**.
  В AD учитываются вложенные группы. `*` в `LDAP_TEACHER_GROUPS` пускает всех, кто может войти в домен.
* **Группу администраторов указывайте полным DN**, как в примере. Имя группы без DN совпадёт с группой
  с таким же названием в любом подразделении домена. Если кто-то может создавать группы хотя бы в одном
  подразделении (например, сотрудник поддержки, которому доверили подразделение студентов), он сможет
  сам стать администратором Zoom Checker. Полный DN группы можно посмотреть в оснастке
  «Active Directory — пользователи и компьютеры» (меню «Вид» → «Дополнительные компоненты», затем
  свойства группы → вкладка «Редактор атрибутов» → `distinguishedName`) или командой PowerShell
  `Get-ADGroup ZoomChecker-Admins`. Проще всего — проверкой `check-ldap --user <логин администратора>`
  (или **Админ → Настройки → Проверка LDAP**): в шаге «Группы» перечислены полные DN всех групп
  пользователя. Если в `LDAP_ADMIN_GROUPS` осталось просто имя, `check-config` об этом предупредит.
  В OpenLDAP DN группы выглядит как
  `cn=zoom-checker-admins,ou=groups,dc=example,dc=com`, во FreeIPA — как
  `cn=zoom-checker-admins,cn=groups,cn=accounts,dc=example,dc=com`. Для группы преподавателей можно
  оставить просто имя.
* `LDAP_CA_FILE` — корневой сертификат вашего центра сертификации. Он нужен, если сертификат контроллера
  домена выпущен внутренним центром сертификации (обычно так и есть). Файл должен читаться службой:
  `sudo chown root:zoom-checker /etc/zoom-checker/corp-ca.pem && sudo chmod 0640 /etc/zoom-checker/corp-ca.pem`.
  В Docker путь указывается внутри контейнера — см. [раздел 4](#4-установка-в-docker).
* Отключённые учётные записи AD не пускаются. Тот, кто уже вошёл, потеряет доступ при следующем входе —
  не позже чем через `EXTERNAL_SESSION_TTL` (24 часа); сразу — если отключить его в **Админ → Пользователи**
  ([раздел 7](#7-первый-вход-и-пользователи)). Пустой пароль отклоняется до обращения к серверу.
* Шифрование: `ldaps://…:636` или `ldap://…:389` + `LDAP_START_TLS=true`. Современные контроллеры
  домена не принимают пароль по незашифрованному соединению. `LDAP_INSECURE_SKIP_VERIFY=true` — только для проверки.
* Пресеты: `ad` (Active Directory, Samba AD), `openldap` (`uid`, `groupOfNames`/`memberOf`), `freeipa`.
  Отдельные атрибуты и фильтр можно переопределить (`LDAP_USER_FILTER`, `LDAP_*_ATTR`).
* Если пользователь с таким же логином есть среди **локальных** учётных записей, проверяется локальный пароль.

Проверка по шагам (подключение, служебный вход, поиск, группы, роль):

```bash
sudo -u zoom-checker /usr/local/bin/zoom-checker check-ldap --user ivanov
```

В Docker: `docker compose run --rm zoom-checker check-ldap --user ivanov`.
То же есть в **Админ → Настройки → Проверка LDAP**.

Правила учёта, которые меняются в интерфейсе (**Админ → Настройки**): имена, которые не считаются
студентами (например «Преподаватель», «Zoom Recorder»), минимальный процент присутствия для отметки
«был» (0 — достаточно одного подключения), окно привязки — за сколько часов до начала занятия может
начаться его конференция (по умолчанию 1; после конца занятия — не позже чем через 30 минут), учёт
организатора.
После сохранения занятия за последние 60 дней пересчитываются автоматически.

## 11. Резервные копии и восстановление

* **SQLite**: каждую ночь (03:30 по `TIMEZONE`) сервис сам делает копию в
  `/var/lib/zoom-checker/backups/zoom-checker-ГГГГ-ММ-ДД.db` и хранит `BACKUP_KEEP` последних.
  Ручная копия на ходу: `sudo -u zoom-checker /usr/local/bin/zoom-checker backup /var/lib/zoom-checker/manual.db`.
  Копируйте каталог `backups/` на другой сервер своими средствами (rsync, borg и т. п.).
* **Восстановление**: `systemctl stop zoom-checker`, заменить `/var/lib/zoom-checker/zoom-checker.db`
  копией (владелец `zoom-checker`), удалить рядом файлы `-wal`/`-shm`, `systemctl start zoom-checker`.
* **PostgreSQL**: обычный `pg_dump -Fc` / `pg_restore`.

## 12. Обновление и удаление

* Обновление: получите новый пакет установки (как в [разделе 3](#как-получить-пакет-установки)),
  распакуйте его на сервере и в его папке запустите `sudo ./install.sh` — установщик возьмёт бинарник,
  лежащий рядом. Настройки и данные сохраняются, миграции базы применяются автоматически.
  Если вы обновляете раннюю версию и в **Админ → Настройки** «Окно привязки» равно 6 (прежнее значение по
  умолчанию), поставьте 1: теперь это только время *до* начала занятия, а после его конца конференция
  привязывается не позже чем через 30 минут.
* Docker: сначала обновите исходный код — `git pull` или распакуйте новый архив поверх старого
  (файл `deploy/.env` останется), — затем `docker compose up -d --build`. Без обновления кода
  `--build` просто пересоберёт ту же версию.
* Удаление: `sudo ./install.sh --uninstall` (данные и настройки остаются) или
  `--uninstall --purge` (удалить всё). Порты, которые открыл сам установщик в firewalld или ufw, при
  удалении закрываются; открытые до него остаются. Для других файрволов установщик напечатает точную
  команду, а без файрвола на сервере напомнит закрыть порты в группе безопасности облака.

## 13. Командная строка

```text
zoom-checker [--config FILE] <команда>
  serve            запустить сервер (по умолчанию)
  check-config     проверить настройки (без вывода секретов), код выхода 1 при ошибке
  version | healthcheck | migrate
  user list | user create --username U --role admin|teacher [--generate] | user set-password U [--generate]
  check-ldap [--user U [--password-stdin]] | check-oidc
  backup FILE
  simulate --meeting ID [--url URL] [--secret S] [--insecure] [--names FILE] [--duration 90m]
           [--speed 30] [--instant] [--seed N] [--no-end] [--dry-run] [--topic ТЕМА] [--host-name ИМЯ]
```

Подробности по каждой команде — `zoom-checker <команда> --help`.

На сервере, установленном через `install.sh`:

* программа лежит в `/usr/local/bin/zoom-checker`. Пишите полный путь: в Oracle Linux, RHEL, Alma и
  Rocky Linux `sudo` не ищет программы в `/usr/local/bin` и отвечает `command not found`;
* файл настроек `/etc/zoom-checker/zoom-checker.env` подхватывается сам — `--config` можно не указывать;
* проверки (`check-config`, `check-ldap`, `check-oidc`) и `backup` запускайте от имени пользователя
  службы: `sudo -u zoom-checker /usr/local/bin/zoom-checker check-config`. Так проверка видит файлы
  так же, как сервис: если он не сможет прочитать ключ или сертификат, вы узнаете об этом до
  перезапуска. Если вы работаете под root и команды `sudo` нет:
  `runuser -u zoom-checker -- /usr/local/bin/zoom-checker check-config`.

В Docker: `docker compose exec zoom-checker /zoom-checker <команда>` (контейнер работает) или
`docker compose run --rm zoom-checker <команда>` (контейнер не запускается).

`simulate` — демонстрация без Zoom: отправляет подписанные события, как настоящий Zoom
(опоздания, переподключения, два устройства, комнаты для групповой работы, неопознанные
«iPhone» и «Ваня», повторная доставка). Создайте группу (имена — в `--names` или встроенные),
занятие с тем же номером конференции **на текущее время** («сейчас») и откройте его — список будет
меняться на глазах. С `--instant` конференция «начинается» на `--duration` раньше текущего момента, и
занятие должно начинаться не позже чем через час после этого: `simulate` сам напишет, на какое время его
создать.

По умолчанию `simulate` отправляет события на `PUBLIC_URL` + `/api/webhooks/zoom` и подписывает их
секретом `ZOOM_WEBHOOK_SECRET_TOKEN`; `--url` и `--secret` заменяют эти значения. Если `PUBLIC_URL`
недоступен с самого сервера (или изнутри контейнера Docker), укажите адрес сервиса напрямую:

* `TLS_MODE=auto`: `--url https://127.0.0.1/api/webhooks/zoom --insecure` (если в `PUBLIC_URL` указан
  порт, добавьте его: `https://127.0.0.1:8443/…`). `--insecure` отключает проверку сертификата: он
  выдан на доменное имя, а не на 127.0.0.1;
* `TLS_MODE=off`: `--url http://127.0.0.1:8080/api/webhooks/zoom` (порт из `LISTEN_ADDR`);
* `TLS_MODE=file`: `--url https://127.0.0.1:<порт из LISTEN_ADDR>/api/webhooks/zoom --insecure`.

## 14. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Zoom не проходит **Validate** | Адрес — с доменным именем, а не IP ([раздел 5](#перейти-с-ip-адреса-на-доменное-имя)); сервис открывается снаружи по https — проверьте с другого компьютера ([раздел 2](#откройте-порты-80-и-443-у-облачного-провайдера)); `ZOOM_WEBHOOK_SECRET_TOKEN` совпадает с Secret Token; время сервера верное (см. строку «Часы сервера расходятся с Zoom»); в журнале `journalctl -u zoom-checker` есть строка о запросе |
| На странице «Zoom» нет событий | Подписка активирована (Activation); организатор конференции — пользователь вашего аккаунта; выбраны нужные события; время сервера верное (см. следующую строку); в Zoom Marketplace есть журнал доставок. Если сервис долго был выключен — см. строку «Сервис долго был выключен» |
| На странице «Zoom» предупреждение «Часы сервера расходятся с Zoom» | Время сервера / NTP: `timedatectl` должен показывать `System clock synchronized: yes`. Включите синхронизацию: `sudo timedatectl set-ntp true` (Docker берёт время у сервера). Если часы сервера спешат больше чем на 2 часа, сервис не принимает события Zoom, и они теряются; в журнале — строка с советом включить NTP |
| Сервис долго был выключен, и события перестали приходить | Zoom отключает подписку, если несколько проверок адреса подряд не прошли (примерно после 2 недель простоя). Zoom Marketplace → ваше приложение → **Feature** → включите подписку → **Validate** → **Save**. Если события всё равно не приходят — удалите подписку и добавьте её заново (шаг 4 [раздела 6](#6-подключение-zoom)). Занятия, которые шли во время простоя, проверьте вручную ([раздел 6](#если-сервис-был-недоступен)) |
| Занятие не «подхватило» конференцию | Номер конференции в занятии совпадает; конференция началась не раньше чем за час до начала занятия (настройка «Окно привязки») и не позже чем через 30 минут после его конца; иначе — на странице занятия «Привязать к этому занятию» (пока конференция идёт) или страница «Zoom» → «Несвязанные сессии» → «Привязать к занятию» |
| Занятие давно закончилось, а всё ещё «Идёт» | Zoom не прислал «End Meeting» (сервис был недоступен дольше повторов Zoom, или событие не отмечено в приложении Zoom — [раздел 6](#6-подключение-zoom)). Нажмите на странице занятия **Завершить занятие**; через 6 часов тишины сервис завершит его сам |
| Два занятия по одной ссылке Zoom: одно посчиталось, второе осталось «Запланировано», все «Не подключался» | Одна конференция засчитывается только одному занятию — совместная лекция или пара подряд без перезапуска конференции. Обходные пути — в [разделе 6](#одна-конференция-zoom--одно-занятие) |
| Студент в «Не идентифицированы» | Его имя в Zoom не совпадает с именем в списке группы. Сопоставьте вручную («Запомнить это имя» — и в следующий раз он опознается сам) |
| Не выдаётся сертификат | Открыты ли порты 80 и 443 у облачного провайдера — проверьте с другого компьютера ([раздел 2](#откройте-порты-80-и-443-у-облачного-провайдера)); верен ли `PUBLIC_URL` и указывает ли DNS-имя на этот сервер; причину показывает строка `could not obtain TLS certificate` в журнале |
| Сервис не запускается после изменения настроек | `journalctl -u zoom-checker -n 50`. Частая причина — служба не может прочитать файл ключа или сертификата: `sudo -u zoom-checker /usr/local/bin/zoom-checker check-config` покажет `permission denied`; выдайте права, как в [разделе 5](#свой-сертификат-tls_modefile) |
| Docker: `docker compose ps` показывает «Restarting» | `docker compose logs zoom-checker`; частая причина — файл сертификата по пути, которого нет внутри контейнера ([раздел 4](#4-установка-в-docker)) |
| `sudo: zoom-checker: command not found` | Укажите полный путь: `sudo /usr/local/bin/zoom-checker …` ([раздел 13](#13-командная-строка)) |
| Не входит пользователь AD/Keycloak | `check-ldap --user …` / `check-oidc`; состоит ли пользователь в нужной группе/роли; в Keycloak группы передаются только с маппером Group Membership ([раздел 8](#8-вход-через-keycloak-openid-connect), шаг 7) |

## 15. Безопасность

* Каждый запрос Zoom проверяется по подписи HMAC-SHA256 и времени; неподписанные отклоняются.
* Секреты хранятся только в файле настроек: `/etc/zoom-checker/zoom-checker.env` (установщик ставит
  права `0640`, владелец root) или `deploy/.env` в Docker (выполните `chmod 600 .env`). В журнал они
  не пишутся.
* Пароли — argon2id; ограничение попыток входа; защита от CSRF; строгие заголовки безопасности (CSP и др.).
* Сервис работает от отдельного пользователя без прав root, с ограничениями systemd.
* Группы и роли администраторов указывайте точно: полным DN в AD/LDAP ([раздел 9](#9-вход-через-active-directory--ldap)),
  ролью realm или полным путём группы в Keycloak ([раздел 8](#8-вход-через-keycloak-openid-connect)).
* Если перед сервисом стоит прокси — обязательно укажите `TRUSTED_PROXIES`, иначе все запросы будут
  выглядеть пришедшими с одного адреса и ограничение попыток входа будет общим для всех.
* Закройте лишние порты сервера (например, веб-консоль Cockpit на 9090, если она не нужна).
